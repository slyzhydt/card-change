# card-change

Windows 本地显示映射工具：指定整张原卡 A 显示成卡面 B，该卡已识别的各个状态一起更换；可分别选择当前九套角色皮肤。保留卡牌和角色的玩法数据。

## 下载与使用

当前整卡测试版已发布：[下载 v0.3.1-test1](https://github.com/slyzhydt/card-change/releases/tag/v0.3.1-test1)。选择 `card-change-0.3.1-test1-windows-x64.zip`，完整解压后运行 `card-change.exe`，不需要安装 Python、Node.js；同页提供对应源码和 SHA256 校验文件。旧版 0.2.1 不包含皮肤选项。

1. 首次点击“从游戏资源准备数据”，选择本机游戏 `gameres/manifest.ssra`。相邻的 `chunks` 分卷需要已下载到本机。
2. 左侧按角色、卡名或编号选整张原卡；右侧选异画卡面、其他卡牌或本地动态异画。同一卡的已识别状态只显示一行。
3. 点“添加 / 替换选中映射”，可逐项开关、删除，保存配置供下次编辑。
4. 点“生成测试副本”，选择已有明文脚本层的游戏程序。程序副本位于工具 `out/trial-.../`，选择结果已内嵌，原文件不覆盖。
5. 手动安装与回滚步骤见 [使用说明](REDIRECTS.md)。只支持已有明文脚本层的输入，编译脚本 .jbin 的还原不属于本工具能力。

包内不含游戏程序、分卷、卡牌表或美术资源；数据由使用者从自己的游戏文件准备。工具不会自动安装或启动游戏。皮肤仅限当前九条经过检查的表项，不开放任意路径修改。

## 按整张卡选择（0.3.1-test1）

例如 c_1057_srt4 与 rsp1～rsp5 六个状态只需添加一次映射；生成器会为六个实际编号写入同一目标的图片、骨架及配套资源。卡牌编号、费用、技能和其他玩法字段分别保持原样，关闭或删除一项作用于整张卡。当前清单的2264个状态编号对应1302张整卡；“其他卡牌”目标列表也按整卡显示，搜索任一成员编号能找到对应卡。

分组使用明确的 rsp／pot／lbk 状态关系，以及有表字段佐证的卡牌引用。没有独立名称的 mut 状态可回到所属卡；独立命名的新卡保留为独立选择。不同卡共用图片、名称相同，都不会仅凭这一点合并。未来清单中无法确认的关系也不会凭空猜测。

新版保存 _editor.version=2、selection_unit=whole_card。载入旧版逐编号配置时，同一卡目标资源和启用状态一致则自动合并，请另存新版；有不同目标或开关冲突时明确拒绝载入，原文件不改。每次修改后仍须重新生成程序副本。展开后的配置受10000个编号及1MB运行时容量限制，超出时生成前明确报错。

七套皮肤的原模型只有 move/stop。本版按用户要求让它们显示在战斗中：保留皮肤原 move/stop，缺少的动作名使用 stop 日常动作的自然速度片段，并保留原动作时长和事件。继续读取原版技能时间线、特效配置，动作队列和完成通知由原生动画系统处理；没有重建攻击、受击等专门姿势。生成时会另外产生 `skinrender-models` 文件夹，手动试用时必须与游戏程序一起复制到游戏 bin。缺文件、校验不符或原生 JSON 加载失败时，该皮肤停用并回落原版。工具下载包不含这些从本机生成的模型。

罗斯薇瑟原大招效果总表已映射，但直接请求原版分镜骨架的入口仍可能漏过；test3 补齐经过动作兼容检查的皮肤分镜骨架、图集、贴图及PNG别名。未声称已经在实机看到大招修复。

按用户选择，希尔德的 special5、海德玛丽的 special6 表情回退到该皮肤 normal；蕾伊的特殊 xxxx 动画回退到 idle，常用动作和表情不改。没有对应皮肤的 front 等特殊资源保留原样。每套独立检查和停用，一套失败不使其他角色配置失效；生成阶段任何选中项检查失败仍会停止生成。

## 天使皮肤说明（沿用 test1）

勾选窗口上方“赛雷妮尔 → 降临沙滩的天使”，保存并重新生成测试副本。可以不添加卡牌映射，单独使用皮肤选项；也可以同时保留卡面选择。开关默认关闭，随配置保存／载入。

生成时从本机资源导出检查皮肤骨架、图集贴图、动作组合、技能配置、效果与粒子依赖；当前样本为 26 条路径、455 项目标依赖。对照默认的 48 个战斗动画、立绘动画和表情，并检查技能挂点与图集片段；失败不生成可用程序。已有皮肤版的头像和立绘资源随之映射，角色账号持有状态不变。

按用户选择，战前特殊演出 `30075_battle_ready`、正面特殊立绘 `30075_front` 保留原样；宣传图、剧情专用原画、卡面等没有列入此角色皮肤资源的文件不会按编号盲改。没有实机验证，不能把离线通过当作所有入口已生效。详情与试用步骤见使用说明。

## 源码运行与构建

需要 Windows、Python 3.11+ 和 Node.js。源码运行先安装 pefile，再运行 `python selector.py`；数据准备和预览需要官方 [ASSet Ripper CLI](https://github.com/cznrip/Chaos-Zero-Nightmare-ASSet-Ripper)，放到 `tools/asset-ripper/ChaosZeroNightmareRipper-CLI.exe`。

```powershell
python -m pip install -r requirements-build.txt
python -m unittest test_mapping test_reliability test_portable test_angel_skin
node dryrun.js
node angel_dryrun.js
node skins_dryrun.js
python build_portable.py --node <node.exe> --ripper <ChaosZeroNightmareRipper-CLI.exe> --node-license <Node-LICENSE> --ripper-license <Ripper-LICENSE> --output dist
```

构建脚本要求新输出目录，保留已有产物。Windows 包内置 Node 运行检查，并内置解包器完成本地数据准备。全部 Python 依赖与运行组件的许可说明见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
